# Agent GhostReaper

LLM 多 Agent 驱动的自主渗透测试系统，仅供授权测试使用。单二进制，内嵌 Web 面板。

## 系统介绍

给定目标与授权范围，系统自主完成渗透测试：拆解任务、执行探测、验证发现、产出报告，人通过面板监督与批准。

- **自主执行**：主宰拆解目标、派发意图，虫群单位领取执行；任一单位干完即驱动下一轮规划，方向随证据调整。
- **唯一账本**：目标、事实、资产、发现全部记入年轮账本，只追加不涂改，任何结论可回溯到原始证据。
- **安全闸门**：增删改数据的动作需人工批准，命中拦截规则直接拒绝，危险动作越不过授权边界。
- **流量留痕**：所有工具流量经镜留存，发现可下钻到原始请求响应，全程可审计。
- **授权即边界**：RoE 面板配置测试目标与操作约束，越界动作不执行。
- **报告可信**：从账本确定性导出（md / csv / json），不经模型生成，每次导出内容一致。

设计核心思想：

- **只记账，不涂改**：一切执行与发现皆为事件，年轮账本是唯一事实源；结论可反驳、可重开，历史永不丢失，当前状态随时可由事件重放重建。
- **事件驱动的探索循环**：新发现记录即唤醒主宰规划——拆解、派发、检查归纳、再规划；资产图与进度图从账本投影，既是发散的燃料，也是收敛的地图。
- **执行成功 ≠ 结论成立**：线索 ≠ 事实，命令成功 ≠ 假设成立，假设成立 ≠ 漏洞已验证，漏洞已验证 ≠ 目标完成——层层把关，不跳步盖章。
- **负向认证**：每个漏洞写成待反证的判断，存在性与影响面分开声明、分开反证，其他可能原因逐条排除；证不倒也证不实，如实记"待确认"，不藏不编。
- **终审归机器，发现者不自证**：目标是否完成、漏洞是否确认，由仲裁者按创建时锁定的完成条件自动判定——只认证据，模型不能自评；验证步骤不派回原发现者。
- **能力开放，边界唯一**：不预设工具、漏洞类别与固定流程，推理与攻击链自由组合；探索的边界只来自授权配置与审批门。

**命名体系**（面板常用词）

| 词 | 意思 |
|----|------|
| 主宰 | 规划大脑：拆任务、派活、检查归纳结果 |
| 牧者 | 对话入口：替你查图答话——问进度、问成果找它 |
| 虫群单位 | 干活的执行者：一只单位领一条任务，干完即销毁 |
| 年轮图 | 任务全部过程的记录图 |
| 账本 | 唯一事实记录：所有操作与发现永久留痕，可回溯 |
| 镜 | 流量记录器：所有请求与响应留底，供审计取证 |
| RoE | 授权面板：划定测试范围与限制 |
| 反证 | 验证工序：一条发现要排除"误判"的可能才算数 |
| 判断 | 一条漏洞条目（发现页里的） |
| 待确认 | 证据不足时的诚实挂起，带原因，可被新证据唤醒 |
| 冬眠 / 唤醒 | 整个任务暂停 / 原地恢复 |
| 已停止 | 任务结束的终态（手动终止、超时或收口结束，不可恢复） |
| 受阻 | 模型连不上，自动等待恢复，恢复后续跑 |
| 插话 | 在会话旁开小窗：问问题或改方向 |
| 插急活 | 给任务加急插入一条工作 |
| 证据包 | 单条发现的完整证据导出（zip） |

## 使用方法

### 产物

| 产物 | 用在 |
|------|------|
| ghostreaper-darwin-arm64 | Mac（Apple 芯片） |
| ghostreaper-darwin-amd64 | Mac（Intel 芯片） |
| ghostreaper-linux-amd64 | Linux 服务器 |
| ghostreaper-windows-amd64.exe | Windows |

### 运行

单文件，放哪个目录，数据就在哪个目录。建议单独建一个文件夹。

**Mac / Linux**

    chmod +x ghostreaper-darwin-arm64    # 文件名按实际平台
    ./ghostreaper-darwin-arm64

Mac 若提示无法打开：右键文件 → 打开，放行一次。

**Windows**

双击 exe，或在 cmd 中运行。虫群执行命令依赖 bash：装 Git for Windows；不装则执行命令报错，面板不受影响。

**通用**

启动后浏览器打开 http://127.0.0.1:28282，首次访问设置面板登录密码。

建议本机安装 nmap（Mac：brew install nmap；Linux：各发行版包管理器）：端口扫描更快；不装也能用，虫群以 bash 完成探测。

同目录会生成三个数据文件，删除后无法恢复，任何时候都不要删：

| 文件 | 是什么 |
|------|--------|
| ghostreaper.db | 账本（任务 / 发现 / 流量记录） |
| ghostreaper.db.key | 加密密钥（丢了加密内容解不开） |
| tasks/ | 任务数据 |

**运行后的目录结构**

    ghostreaper-darwin-arm64      程序本体（以 Mac 为例）
    ghostreaper.db                账本
    ghostreaper.db-shm            账本伴生文件（运行时自动出现）
    ghostreaper.db-wal            同上
    ghostreaper.db.key            加密密钥
    logs/                         运行日志（出问题时可发给别人排查，不含密钥和口令）
    tasks/
    ├── t-a1b2c3d4/               每个任务一个目录
    │   ├── transcripts/          会话记录
    │   └── is1/ is2/ …           各步骤工作目录
    ├── blobs/                    大对象存储（流量原文等）
    └── skills/                   文风 skill（首次运行自动生成）


### 更新版本

新文件覆盖旧文件，按上面方式重新运行。

更新时用新的可执行文件覆盖旧的即可，数据不受影响；正在跑的任务重启后自动接上。

## 版本更新记录

### v1.2.1（2026-11-09）

- 修复范围误判：给域名测域名时，浏览器版本号、请求头和测试参数里的网址不再被当成越界目标误拦。
- 范围审批改版：要测授权外的目标时先拦下等你批准，批准后原会话接着干；红队任务直接测、可随时叫停。
- 审批界面统一：所有审批卡一个样子，批准时可以附一句要求带给虫群；审批记录能翻到底，点开看全部详情。
- 建任务更直观：填资产时实时显示能测多大范围，描述里"只测某某"会自动填到对应位置。
- 牧者全权：在对话里就能改目标、资产、注意事项、优先级，停掉其他方向只做一件事，或冬眠、终止任务。
- 验证不再装死：被打断的验证自动重新派人接着干；验完证伪的直接标"不成立"，不再挂着"待确认"。
- 发现页改四栏：假设、事实、锤炼、成果，东西从左往右流动，出了结果的不再混在正在验的里面。
- 反证过程说人话：每轮按"疑点、怎么验的、结论"三段呈现，看不懂的机器原文折叠保留。
- 模型切换不再连环卡死：各家模型的思考内容按各家规矩传，主备切换、跨格式续跑都稳了。
- 全面提速：大账本任务各页面从卡顿到秒开，年轮图从两分半冻结提速到一秒内出图；界面文字按报告标准重写。

### v1.2.0（2026-11-07）

- 任务不再"假死"：修复两个会导致任务停摆的缺陷——模型接口无响应时现在 5 分钟自动断开并重试（此前会永远等待）；手里活全部完成但目标未达成时，系统继续规划下一步（此前会因"没有新事件"永久停摆）。
- 任务结束后状态如实收场：终止或完成的任务不再残留"排队中""验证中"等过期状态，工作台与虫群列表随之归零。
- 面板大幅提速：发现、虫群会话、任务列表改为按需加载，即点即开；此前一个大型任务能拖慢所有页面数十秒至数分钟。
- 数据库自动维护：写入暂存自动回收，不再无限膨胀拖慢读写；此前实测可涨至 855MB。
- 长任务成本下降：工具的大段输出自动存档（对话内保留索引，可按需读回），长对话不再随轮次线性膨胀。
- 后台命令设限：输出超 100MB 自动截断、超 30 分钟自动结束，杜绝单条命令刷出数十 GB 垃圾文件。
- 资产范围管理：给域名只测该域名，给 IP 测整台服务器；新建任务必选"渗透"或"红队"类型——渗透任务发现的新资产需批准后测试，红队任务直接测试；可随时摘除某个资产，相关在途步骤自动终止。
- 任务创建支持草稿：表单填一半可暂存，从任务列表随时继续；删除任务时可勾选"同时删除相关数据和账本"。
- 建任务新增"注意事项"：写明"用小字典、不要修改数据"等要求，虫群全程遵守，也可从描述一键提取。
- 换模型立即生效：切换主用模型后，所有在跑会话下一轮请求即走新模型。
- 成果/事实"深入"指令：任何一条发现（含已废弃的）可发起深入，可选填方向，系统立即规划执行。
- 未读提醒：成果和事实页有新确认内容时自动亮红点，看过即消。
- 复现步骤只保留必要步骤，每步说明动作与目的，请求包可直接复制到 Burp 发送。
- 冬眠任务释放并发名额，排队任务自动补位；任务并发上限可在系统设置中调整（默认 2）。
- 在途状态实时刷新（历史记录标注截至时间），已取消、已中止如实显示。
- 勾选操作即时响应，失败自动回弹；程序崩溃时堆栈写入运行日志。

### v1.1.0（2026-10-26）

- 派活有闸门：之前 AI 会不停领新活，干不过来就堆着，一个任务能积压几十条等几小时。现在同时在干加在排队的活有上限，干完一条补一条；已经过时的待办自动取消。任务跑得再久也不会越堆越多。
- 报告只有真漏洞：之前一些没实际危害的观察（比如验证码能自动过、端口一直开着）也被当成漏洞写进报告，看着热闹其实没用。现在这类内容只记为过程记录，报告里留下的条条都是需要处理的问题，级别也按统一标准校准。
- 模型断了不再丢进度：之前模型闪断三次，正在干活的单位就被放弃。现在改为原地等待、模型恢复后接着干；还修复了一个长对话导致请求损坏、单位被连环误杀的缺陷。任务状态一次只显示一种，不再同时挂两个状态让人误解。
- 界面整体换新：全新的深色与浅色两套主题，打开时自动跟随系统设置；面板底部显示版本号。
- 字体与排版统一：数字用等宽字体不再跳动，字号只分五级，间距统一取档，弹窗、抽屉与页面用同一套尺寸规则——整体观感不再杂乱。
- 发现页一眼看懂：每条发现分清是“还在验证中”还是“已有结论”，鼠标悬停有说明，状态词从 12 个精简到 6 个，未处理条目数量在页顶直接可见。
- 审批不再连环弹窗：同一件事批准一次后，后续命令不再逐条请求批准；每张待决卡新增危害说明——这条命令要做什么、目标会发生什么变化、最坏后果是什么。
- 诊断包按需导出：可以只导出某类日志（比如只看报错），也可以附加账本和会话记录用于深入排查；日志固定全量记录。
